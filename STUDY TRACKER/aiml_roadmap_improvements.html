D-01 · Visual Design
Minimum Font Size Violations
🔴 Critical Design Effort ●○○
▸ The Problem
Multiple UI elements use illegibly small font sizes. phase-time is 8px, phase-label is 9px, group-label is 9px, nav button text is 10px, filter button text is 9px, and time badges are also 9px. WCAG 2.1 AA requires a minimum of 12px for non-decorative text, and comfortable reading requires 12–13px minimum for labels. This fails accessibility standards and strains the eye, especially on standard-resolution displays.
▸ The Fix
Apply a global minimum of 11px for all label text and 12px for anything a user must read. Specifically: phase labels → 11px, phase time → 11px, group labels → 11px, filter buttons → 11px, time badges → 11px, nav buttons → 11px. This is a pure CSS change with no layout impact.
▸ Code Fix

.phase-time   { font-size: 8px; }
.group-label  { font-size: 9px; }
.filter-btn   { font-size: 9px; }
.time-badge   { font-size: 10px; }
.nav-btn      { font-size: 10px; }

/* After — all bumped to 11px minimum */
.phase-label  { font-size: 11px; }
.phase-time   { font-size: 11px; }
.group-label  { font-size: 11px; letter-spacing: 2px; }
.filter-btn   { font-size: 11px; }

D-03 · Visual Design
Phase Timeline Connector Line Misalignment
🟡 Moderate Design Effort ●○○
▸ The Problem
The connector line between phase dots is drawn using .phase-item::after with left:50%; right:-50%. This creates a visual gap or overlap depending on the viewport width, because the connector does not truly connect center-to-center — it extends 50% to the right from the center, which can be longer or shorter than the actual gap between phase dots. On viewports below 700px it noticeably misaligns.
▸ The Fix
Replace the CSS pseudo-element connector with an SVG-based approach or a simpler method using a full-width background line behind the dots. Position a single horizontal rule behind all the phase items using absolute positioning on the parent container. This guarantees perfect alignment regardless of viewport width.

  position: relative;

  position: absolute;

U-01 · UX & Interaction
Progress Lost on Tab Close (sessionStorage → localStorage)
🔴 Critical UX Effort ●○○
▸ The Problem
All checkbox progress is saved to sessionStorage under the key 'ml_progress'. Session storage is wiped when the browser tab is closed. A learner who spends 30 minutes marking topics complete, then closes the tab or restarts their browser, loses every checkmark. For a learning roadmap — the primary use case of which is tracking multi-week progress — this is a critical UX failure.
▸ The Fix
Replace all instances of sessionStorage with localStorage. This is literally a find-and-replace of one word with zero architectural changes. Optionally, add a "Reset Progress" button in the progress summary widget to allow users to clear stored state intentionally.
▸ One-Line Fix
// Before (progress lost on tab close)
sessionStorage.setItem('ml_progress', JSON.stringify(checkState));
const saved = JSON.parse(sessionStorage.getItem('ml_progress') || '{}');

// After (persists across sessions)
localStorage.setItem('ml_progress', JSON.stringify(checkState));
const saved = JSON.parse(localStorage.getItem('ml_progress') || '{}');

// Add a reset button in the progress summary:
function resetProgress() {
  if (!confirm('Clear all progress?')) return;
  localStorage.removeItem('ml_progress');
  document.querySelectorAll('.topic-card input[type=checkbox]')
    .forEach(c => { c.checked = false; c.closest('.tc-check').classList.remove('done'); });
  updateProgress(document.createElement('input'));
}

U-04 · UX & Interaction
Search Resets innerHTML — XSS Risk and Text Loss
🔴 Critical UX Effort ●○○
▸ The Problem
The search function does: el.innerHTML = el.textContent to reset, then replaces with a regex that wraps matched text in <mark> tags. This has two issues. (1) If any topic name or description contains an ampersand, angle bracket, or quote character that was originally HTML-encoded, el.textContent will decode it and re-setting innerHTML may create broken markup. (2) Using innerHTML with a regex replacement on user-input is a mild XSS vector if user types <img src=x onerror=alert(1)> — the regex wraps it in a <mark> but the inner HTML still executes.
▸ The Fix
Sanitize the search term before injecting it into the regex. Use escapeHTML() on the term, or better yet, use a TreeWalker to wrap text nodes directly without touching innerHTML. This also fixes the text-loss edge case.
▸ Safe Highlight Function
function escapeHTML(str) {
  return str.replace(/[<>"'&]/g, c => ({
    '&':'&amp;','<':'&lt;','>':'&gt;',
    '"':'&quot;',"'":'&#39;'
  }[c]));
}

function doSearch(q) {
  const term = q.toLowerCase().trim();
  const safeTerm = escapeHTML(term); // sanitize before regex
  document.querySelectorAll('.topic-card').forEach(card => {
    const text = card.textContent.toLowerCase();
    const show = !term || text.includes(term);
    card.style.display = show ? '' : 'none';
    card.querySelectorAll('.tc-name,.tc-desc').forEach(el => {
      if (!term) { el.innerHTML = el.textContent; return; }
      const re = new RegExp(`(${safeTerm})`, 'gi');
      // Use textContent as base, escape it, then do replace
      el.innerHTML = escapeHTML(el.textContent)
        .replace(re, '<mark class="highlight">$1</mark>');
    });
  });
}

I-01 · Information Architecture
No Career Path / Role Selector
🔴 Critical Info Architecture Effort ●●●
▸ The Problem
The roadmap presents one single learning path for everyone. But the field has at least four distinct careers with very different required skills: ML Engineer (deployment, infra, production systems), Research Scientist (math depth, paper reading, novel architectures), Data Scientist (statistics, business analytics, visualization), and AI/LLM Product Engineer (prompt engineering, RAG, agents, API integration). A student pursuing a Data Science role doesn't need Flash Attention or PPO — but a research role doesn't need FastAPI or Docker as urgently. Without role targeting, the roadmap is equally relevant to everyone and therefore optimally tailored to no one.
▸ The Fix
Add a "Choose Your Path" modal or section at the top with 4 role cards. Each role sets a data-role attribute on the body. Cards tagged for that role get a green glow border, while optional/irrelevant cards get a muted opacity. Include a small "Relevance" badge per card: "Essential for MLE," "Research priority," etc. Also add an estimated salary range and example job titles per path to motivate the choice.

T-03 · Technical
section.open max-height:9999px Causes Layout Jank
🟢 Performance Technical Effort ●○○
▸ The Problem
Section expand animations use max-height: 9999px as the open state, with transition: max-height 0.5s cubic-bezier(0.4,0,0.2,1). The browser animates from 0 to 9999px, which means the actual visible content (say, 600px tall) animates through a 9999px range — the easing curve only looks natural for the first ~6% of the transition. This causes the expand animation to appear instant and the close animation to appear sluggish. Additionally, sections with a lot of content (quiz + projects + resources) may be >3000px, causing layout recalculations on expand.
▸ The Fix — JS-based height calculation
Measure the actual scrollHeight of each section body in JavaScript and set it as the target max-height explicitly before transitioning. This gives the correct animation curve. Alternatively, use the newer CSS grid-template-rows: 0fr / 1fr animation technique which animates to the intrinsic height without needing JS.
▸ CSS Grid Accordion (Modern Fix)
/* CSS: replace max-height with grid-row animation */
.sec-body {
  display: grid;
  grid-template-rows: 0fr;
  transition: grid-template-rows 0.4s cubic-bezier(0.4,0,0.2,1);
}
.section.open .sec-body {
  grid-template-rows: 1fr;
}
.sec-inner {
  overflow: hidden; /* required for 0fr to clip content */
  min-height: 0;   /* required for 0fr to work in some browsers */
}
